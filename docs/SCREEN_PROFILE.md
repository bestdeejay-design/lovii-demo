## 1. Назначение

Единый центр управления клиента: кошелёк (карты + счёт), история операций по каждой карте, статус программы, настройки приложения, уведомления и безопасность. Экран отвечает на три вопроса: «сколько у меня и где», «что происходило» и «чем я управляю».

Принцип компоновки: **карта = контекст**. Выбор карты в карусели переключает всё «денежное» пространство ниже — счёт и историю. Настройки живут своей зоной ниже и от карт не зависят.

## 2. Навигация

Экран = 5-й таб нижней навигации (`profile`), как сейчас. Роли (МСП / представитель / амбасадор / бизнес-кабинеты) остаются внутри профиля секцией «Роли и кабинеты» — отдельная навигация не вводится.

## 3. Структура (блоки сверху вниз)

| № | Блок | Содержимое | Источник |
|---|------|-----------|----------|
| 1 | **Шапка участника** | аватар, имя, телефон, бейдж уровня (skin-цвет уровня) | есть, без изменений |
| 2 | **Кошелёк — карусель карт** | 4 слайда: LOVII PAY / LOVII PASS / LOVII VIP / LOVII BUSINESS. Под каруселью — **цветные мини-превью** (миниатюры карт) вместо точек-навигации: PAY серебро · PASS розовый · VIP чёрное золото · BUSINESS тиффани. Свайп и клик по мини-превью переключают слайд; активное мини-превью — кольцо + подпись | новый паттерн (было: точки в витрине привилегий + уровни в статус-карте) |
| 3 | **Счёт активной карты** | личная (PAY/PASS/VIP — один счёт): баланс ₽ «1 балл = 1 ₽», кэшбек за месяц, покупки за месяц, выведено через СБП, кнопка «Вывести». BUSINESS: оборот/мес, поступления, баллы клиентов, выплаты | есть, условие — активная карта |
| 4 | **История активной карты** | личная: табы Все / Начисления / Покупки / Списания, группировка по дням. BUSINESS: Поступление / Баллы клиентов / Выплата | есть, условие — активная карта |
| 5 | **Статус и привилегии** | прогресс уровней PAY → PASS → VIP (подписка / оборот 300 000 ₽), полоса прогресса, следующая цель; витрина привилегий (плитки) | объединение секций 5 и 6 текущей сборки |
| 6 | **Избранные МСП** | список избранного, удаление ♥ | есть, без изменений |
| 7 | **Настройки** (3 группы строк) | см. §4 | **возвращается** (полностью отсутствовала) |
| 8 | **Роли и кабинеты** | Роли + Демо-доступ + Установить приложение | есть, переносим установку PWA в §4 «Приложение» |
| 9 | **Футер** | оферты, реквизиты ООО «Аксиома», метка сборки | есть, без изменений |

**Канон-примечание к карусели (важно):** PAY / PASS / VIP — это **одна карта и один счёт**, меняется только оформление (канон 2026-09-12). Поэтому на слайдах 1–3 номер, держатель, счёт и история идентичны — карусель показывает «какие бывают характеры», а не три разных кошелька. BUSINESS — отдельная карта точки со своим счётом и своей историей. Пункт «история по каждой карте» выполняется для пары «личная ↔ BUSINESS».

## 4. Настройки — детализация (блок 7)

Секция «Настройки» = три `list-card`-группы, каждая строка ≥44px, вся строка тапается, справа свитч или chevron (SZ-002).

### 4.1 Приложение
- **Тема** — свитч/сегмент светлая · тёмная (механизм `data-theme` + `lovii_theme` уже есть; переносим из иконки шапки сюда, иконку-дубль в шапке убираем).
- **Город / район** — строка с текущим значением → существующий bottom-sheet выбора района.
- **Установить приложение** — существующая install-строка PWA.
- **О приложении** — версия сборки («сборка N»), ссылка на этот экран-спеку не нужна, просто метка.

### 4.2 Уведомления
- **Мастер-свитч «Пуши»** — при первом включении запрашивает permission браузера (в демо Notification API; прод-канал — по `PUSH_NOTIFICATIONS_SPEC.md`).
- Типы (свитчи, видны при включённом мастере): **Заказы** · **Начисления баллов** · **Акции и Flash Deals** · **Новости моих МСП**.
- Если браузер запретил пуши — подпись «Разреши уведомления в настройках браузера», свитчи задизейблены.

### 4.3 Безопасность
- **PIN-код** — установить / изменить / отключить. Пин-пад: 4 цифры, ввод дважды с подтверждением. Хранение: **только на устройстве** — `localStorage`, SHA-256(соль + пин); голый пин не хранится и на бэкенд не уходит (подтверждение гипотезы владельца).
- **Face ID / отпечаток** — WebAuthn platform authenticator (реальный API). Доступен только при установленном PIN. На платформах без поддержки строка скрыта (не задизейблена).
- **Выйти** — сброс локального состояния демо (tx, избранное, настройки) с подтверждением в bottom-sheet.

### 4.4 PIN-лок (следствие)
Если PIN установлен → при загрузке демо показывается **экран блокировки**: логотип, 4 точки ввода, пин-пад, кнопка Face ID (если привязан). Неверный PIN — shake-анимация и очистка. Это закрывает претензию «пинкод так и не появился на экране входа»: в демо lock-экран появляется сразу после установки PIN в настройках.

**Новое — после аппрува спеки фиксируем в lovii-design (правило «сначала в канон»):**
1. `mini-card` — цветное мини-превью карты (индикатор+переключатель карусели): размеры, кольцо активности, 4 тона скинов.
2. `switch-row` — строка настройки со свитчем (состояния on/off/disabled).
3. `pin-pad` — цифровая клавиатура + точки ввода + shake-ошибка.
4. `lock-screen` — паттерн экрана блокировки.

## 7. Состояния

- Пустая история категории — существующая заглушка.
- Пустое избранное МСП — существующая заглушка.
- Пуши запрещены браузером — подпись + disabled свитчи.
- WebAuthn недоступен — строка Face ID скрыта.
- PIN не установлен — lock-экран не показывается, строка Face ID скрыта.
- Неверный PIN — shake + очистка ввода (счётчик попыток в демо не блокирует).
