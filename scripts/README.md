# Проверки витрины (`scripts/`)

Две проверки без зависимостей — запускаются из корня репозитория:

```bash
python3 scripts/check-theme.py            # отчёт по зашитым цветам
python3 scripts/check-theme.py --strict   # код 1, если есть находки (для CI)
python3 scripts/check-classes.py          # новые/удалённые классы против эталона
python3 scripts/check-classes.py --strict # код 1, если появились новые классы
python3 scripts/check-classes.py --update # перезаписать эталон после осознанного решения
```

## Что ловит каждая

| Проверка | Что ищет | Чего НЕ ловит |
|---|---|---|
| `check-theme.py` | зашитые `#hex` / `rgba()` в `color`, `background-color`, `border-color`, `fill`, `stroke` вне слоя токенов | тени и градиенты (наложения поверх фото, брендовые поверхности карт — исключены осознанно), а также *неподходящий*, но существующий токен |
| `check-classes.py` | новые классы в `css/lovii.css` — повод лишний раз спросить «это композиция системного блока или новая визуальная роль?» | не проверяет, действительно ли класс нужен — это разговор, а не автоматика |

Список системных блоков для композиции: `.card` · `.list-card` · `.row-item` · `.sr-ico` · `.ri-mid` · `.chev` · `.app-badge` · `.acc-field` · `.acct__btn` · `.link-btn` · `.seg` · `.qty` · `.st-chip` · `.sum-row/.sum-div/.sum-total` · `.toast`.

## Чего автоматика не заменяет

Проверки закрывают механические ошибки. Всё, что касается раскладки и иерархии, ловится только съёмкой кадров и замером геометрии, поэтому в конце каждой правки:

1. Снять кадры: ключевые маршруты × 390/768/1280 × светлая и тёмная тема.
2. Сверить с предыдущим состоянием попиксельно (отличия только там, где их ждёшь).
3. Прогнать обход рантайма: 0 ошибок консоли, 0 горизонтальных переполнений.
4. Замерить геометрию изменённых блоков (ширины, отступы, выравнивание правых краёв, зазоры до липких панелей).
5. Поднять `?v=` у изменённых скриптов и CSS в `index.html` — иначе service worker отдаст старые файлы.
